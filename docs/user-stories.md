# User Stories — Team Tasks

> 페르소나: **P1 김지훈** — 개발팀 리드 (5년차), 중급 기술 수준

---

## 1. 핵심 시나리오

### 하루 일과 흐름 (월요일 기준)

---

#### 09:00 — 출근, 오늘 판 한눈에 보기

김지훈은 자리에 앉자마자 브라우저에서 Team Tasks를 연다.  
로그인 없이 바로 Kanban 보드가 뜬다.

- **Todo** 열에 새로 쌓인 카드 3장을 확인한다.
- **In Progress** 열에 어제부터 이어진 일감이 5개 있다.
- 마감일이 오늘인 카드가 빨간 날짜로 표시된 것을 발견한다.

> **기대 결과:** 보드를 열자마자 팀 전체 상황을 30초 안에 파악한다.

---

#### 09:15 — 담당자 미배정 일감 처리

필터에서 **담당자 → 미배정** 을 선택한다.  
Todo 열에 담당자 없는 카드 2장이 남는다.

1. 첫 번째 카드를 클릭 → 수정 다이얼로그 열기  
2. 담당자를 **이수진** 으로 설정, 우선순위를 **높음** 으로 올린다.  
3. **수정 완료** 클릭 → 카드에 이수진 아바타가 즉시 나타난다.
4. 두 번째 카드도 같은 방식으로 **박민준** 에게 배정한다.

> **기대 결과:** 미배정 일감 0개. 필터 초기화 후 전체 보드 복귀.

---

#### 10:30 — 긴급 이슈 등록

슬랙에서 운영팀이 결제 오류를 제보한다.  
김지훈은 보드 우측 상단 **새 일감** 버튼을 클릭한다.

| 필드 | 입력값 |
|------|--------|
| 제목 | `[긴급] 결제 모듈 오류 재현 및 원인 파악` |
| 상태 | In Progress |
| 우선순위 | 긴급 |
| 담당자 | 이수진 |
| 마감일 | 오늘 |

**추가** 클릭 → In Progress 열 최상단에 빨간 테두리 카드가 생긴다.  
슬랙에 카드 내용을 복붙해 이수진에게 공유한다.

> **기대 결과:** 긴급 카드가 1분 안에 보드에 올라간다.

---

#### 12:00 — 점심 전 빠른 확인

자리를 뜨기 전 보드를 한 번 훑는다.  
이수진이 긴급 카드를 **Review** 열로 옮겨 놓은 것을 확인한다.  
별도 조치 없이 자리를 뜬다.

> **기대 결과:** 이동된 상태가 실시간으로 반영되어 있다.

---

#### 14:00 — 오래된 In Progress 카드 정리

필터에서 **우선순위 → 높음** 을 선택한다.  
3일 넘게 In Progress에 머문 카드를 발견한다.

- 카드를 클릭 → 설명란에 `블로커: 외부 API 응답 지연 중` 추가.
- 우선순위를 **긴급** 으로 올린다.
- 수정 완료 → 팀원에게 맥락이 담긴 카드로 상황 전달.

> **기대 결과:** 설명이 카드에 즉시 반영된다. 별도 메신저 없이 맥락 공유.

---

#### 16:30 — 신규 팀원 온보딩

오늘 합류한 팀원 **최다은** 을 앱에 등록한다.

1. 헤더의 **팀원 관리** 버튼 클릭.
2. 이름 입력 → **추가** 클릭 → 팀원 목록에 즉시 추가된다.
3. 기존 미배정 Todo 카드 하나를 최다은에게 배정한다.

> **기대 결과:** 팀원 등록에서 일감 배정까지 2분 내 완료.

---

#### 18:00 — 퇴근 전 데일리 마무리

필터 초기화 후 전체 보드를 최종 확인한다.

- **Done** 열: 오늘 완료 카드 4장.
- **In Progress** 열: 진행 중 카드 6장, 마감 초과 없음.
- **Todo** 열: 내일 시작할 카드 정렬 완료.

브라우저 탭을 닫는다. localStorage에 상태가 저장되어 내일 출근 시 그대로 복원된다.

> **기대 결과:** 별도 저장 버튼 없이 데이터가 유지된다.

---

### 시나리오 요약

| 시간 | 행동 | 사용 기능 |
|------|------|-----------|
| 09:00 | 전체 현황 파악 | Kanban 보드, 마감일 표시 |
| 09:15 | 미배정 일감 배정 | 담당자 필터, 일감 수정 |
| 10:30 | 긴급 일감 등록 | 새 일감 추가, 우선순위 설정 |
| 12:00 | 상태 변경 확인 | 보드 열람 |
| 14:00 | 블로커 기록 | 일감 수정, 설명 추가 |
| 16:30 | 신규 팀원 등록·배정 | 팀원 관리, 담당자 배정 |
| 18:00 | 일과 마무리 확인 | 전체 보드, localStorage 자동 저장 |

## 2. 결정 사항

시나리오를 구현하기 전에 팀이 합의해야 할 질문 5개입니다.

| # | 질문 | 관련 시나리오 | 선택지 |
|---|------|--------------|--------|
| D1 | **누구나 모든 일감을 수정·삭제할 수 있는가?** 담당자가 아닌 팀원도 다른 사람의 카드를 편집할 수 있어야 하는가? | 09:15 담당자 배정, 14:00 블로커 기록 | A) 전원 가능 (현행 MVP) B) 담당자 + 팀장만 가능 |
| D2 | **일감 상태 이동에 순서 제약을 둘 것인가?** Todo → Done 처럼 단계를 건너뛰는 이동을 허용할 것인가? | 10:30 긴급 카드를 In Progress로 직접 등록 | A) 자유 이동 허용 (현행 MVP) B) 인접 열로만 이동 가능 |
| D3 | **마감일 초과 시 알림을 보낼 것인가?** 빨간 표시 외에 별도 알림(슬랙·이메일)이 필요한가? | 09:00 마감일 초과 카드 발견 | A) 시각적 표시만 (현행 MVP) B) 외부 알림 연동 |
| D4 | **팀원을 삭제하면 해당 일감을 어떻게 처리할 것인가?** 담당자가 빠진 일감을 미배정으로 둘 것인가, 삭제를 막을 것인가? | 16:30 신규 팀원 온보딩 (역방향: 기존 팀원 삭제) | A) 자동으로 미배정 처리 (현행 MVP) B) 일감이 있으면 삭제 불가 |
| D5 | **보드 데이터를 여러 기기·브라우저 간에 공유할 것인가?** localStorage는 같은 브라우저에서만 유지되는데, 팀 전체가 동일한 보드를 봐야 하는가? | 18:00 퇴근 후 데이터 유지 | A) 브라우저 단독 저장 (현행 MVP) B) 공유 URL 또는 백엔드 동기화 |
